# Neatoo 0.26.2

**Release Date:** 2026-04-05
**Type:** Patch
**Breaking Changes:** No

---

## Summary

Adds a `Disabled` parameter to all MudNeatoo input components. Previously, passing `Disabled` to any MudNeatoo component threw `InvalidOperationException` at runtime because the parameter didn't exist.

---

## What Changed

### MudNeatoo Components Accept a `Disabled` Parameter

All 11 MudNeatoo input components now expose an optional `[Parameter] public bool Disabled { get; set; }` (default `false`). The inner MudBlazor component is disabled when either `EntityProperty.IsBusy` is true or the caller passes `Disabled="true"`:

```razor
@* Disable based on business state *@
<MudNeatooTextField T="string"
                    EntityProperty="@entity[nameof(IOrder.ShippingAddress)]"
                    Disabled="@(!entity.RequiresShipping)" />
```

Components updated: `MudNeatooTextField`, `MudNeatooNumericField`, `MudNeatooSelect`, `MudNeatooDatePicker`, `MudNeatooCheckBox`, `MudNeatooRadioGroup`, `MudNeatooSwitch`, `MudNeatooSlider`, `MudNeatooAutocomplete`, `MudNeatooTimePicker`, `MudNeatooDateRangePicker`.

---

## Migration

No migration needed. Existing usage without `Disabled` is unchanged — components default to disabling only when `IsBusy` is true.
