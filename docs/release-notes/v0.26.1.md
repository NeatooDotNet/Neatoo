# Neatoo 0.26.1

**Release Date:** 2026-04-04
**Type:** Patch
**Breaking Changes:** No

---

## Summary

Fixes a rule ID collision bug where derived classes that registered rules in their constructors would crash with `ArgumentException` because the generated `GetRuleId` ordinals overlapped with base class ordinals.

---

## What Changed

### Hash-Based Rule IDs Replace Sequential Ordinals

The source generator previously assigned sequential ordinal IDs (`1u, 2u, 3u...`) starting at `1u` in every class's generated `GetRuleId` override. When a derived class inherited from a base class that also had rules, both produced overlapping IDs. At runtime, `RuleManager.RegisterRule` called `Dictionary.Add(ruleId, rule)` which threw on the duplicate key.

Generated `GetRuleId` now uses FNV-1a hash-based IDs derived from the source expression content:

```csharp
// Before (0.26.0) — ordinals collide across inheritance
@"t => t.Foo = t.A + t.B" => 1u,  // BaseClass
@"t => t.Bar = t.C"       => 1u,  // DerivedClass — COLLISION

// After (0.26.1) — hashes are unique per expression
@"t => t.Foo = t.A + t.B" => 0xA1B2C3D4u,  // BaseClass
@"t => t.Bar = t.C"       => 0xE5F6A7B8u,  // DerivedClass — no collision
```

The generator's hash function matches `ValidateBase.ComputeRuleIdHash` exactly, so dynamically registered rules produce consistent IDs.

---

## Migration

No migration needed. This is an internal change to generated code. Existing serialized rule state from 0.26.0 will re-serialize with new IDs on first round-trip — rule matching is by expression content, not by stored ID values.
