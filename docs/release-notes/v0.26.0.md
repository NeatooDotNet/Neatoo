# Neatoo 0.26.0

**Release Date:** 2026-04-04
**Type:** Feature
**Breaking Changes:** No

---

## Summary

Adds opt-in trace-level logging for entity/list JSON serialization and factory lifecycle. Uses `[LoggerMessage]` source generation for zero-allocation diagnostics when disabled. Updates RemoteFactory dependency to 0.28.0.

---

## What's New

### Trace-Level Framework Diagnostics

Neatoo now emits structured `LogLevel.Trace` messages under the `"Neatoo.Trace"` logging category. When trace logging is disabled (the default), overhead is limited to `Stopwatch` allocations at serialization boundaries.

Instrumented areas:
- **Entity JSON serialization** (read/write) -- type resolution, property deserialization, property manager hydration, write completion with property counts
- **List JSON serialization** (read/write) -- item-level deserialization timing, deleted item counts, total write timing
- **`FactoryComplete` lifecycle** -- operation start/finish with entity state (`IsNew`, `IsDeleted`, `IsModified`)

All log messages use `[LoggerMessage]` source generation with structured parameters and event IDs in the 10000-10499 range.

### Enabling Trace Logging

Configure your logging provider to enable the `Neatoo.Trace` category at `Trace` level:

```json
{
  "Logging": {
    "LogLevel": {
      "Neatoo.Trace": "Trace"
    }
  }
}
```

When `ILoggerFactory` is registered in DI (standard in ASP.NET Core), Neatoo automatically uses it. Otherwise, logging falls back to `NullLogger`.

### Dependency Update

- `Neatoo.RemoteFactory` 0.26.0 -> 0.28.0
- `Neatoo.RemoteFactory.AspNetCore` 0.26.0 -> 0.28.0
