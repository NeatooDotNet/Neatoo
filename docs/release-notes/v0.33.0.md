# v0.33.0

**Release date:** TBD
**Breaking changes:** Yes

## Summary

The `IsChild` flag is gone. `IsSavable` no longer has a `!IsChild` term, `Save()` no longer guards on it, and `SaveFailureReason.IsChildObject` is removed. Root-versus-child is declared in the type system — a root entity interface extends `IEntityRoot`, a child entity interface extends `IEntityBase` — and that is now the only mechanism that keeps consumers from saving a child.

## Why

`IsChild` was sold as a save barrier, but it was never the thing doing the work, and it was never applied consistently.

**It was only ever set by `EntityListBase`.** `MarkAsChild()` had exactly two call sites, both in `EntityListBase.InsertItem`. A child entity held as a *direct property* — `order.ShippingAddress`, `parent.Child` — never got it. The framework's own test for that case had to call `MarkAsChild()` by hand in setup, because nothing else would.

**Where it was set, it did not add safety.** `Delete()` routes through `ContainingList`, not `IsChild`. Child `[Insert]`/`[Update]` methods take the parent entity or parent ID, so an outside caller cannot invoke them. Entity classes are `internal`. The barrier was already complete without a flag.

**It actively caused a bug.** `IsSavable` returning `false` on a modified child led save-cascade code to conclude the child did not need persisting — a real production defect in a consuming application. The flag did not prevent an unsupported save; it broke a supported one.

The genuine guarantee is the interface split. `EntityBase<T>` implements both `IEntityBase` and `IEntityRoot`, so every *concrete* has `IsSavable` and `Save()` — but consumers hold interfaces, entity classes are `internal`, and a child interface has no `Save()` to call. The mistake becomes a compile error instead of a runtime exception that only fires half the time.

## What's new

### Core semantics

```csharp
// before
IsSavable => (IsModified || IsNew) && IsValid && !IsBusy && !IsChild;

// after
IsSavable => (IsModified || IsNew) && IsValid && !IsBusy;
```

`IsSavable` now says only "this object has a reason to persist and nothing is blocking it." It says nothing about position in an aggregate.

### Removed

| Member | Location |
|---|---|
| `IsChild` | `EntityBase<T>`, `IEntityMetaProperties`, `EntityListBase<I>`, `EntityLazyLoad<T>` |
| `MarkAsChild()` | `EntityBase<T>` (protected), `IEntityBaseInternal` |
| `SaveFailureReason.IsChildObject` | `Neatoo.Exceptions` |
| The `IsChild` guard in `Save()` | `EntityBase<T>.Save()` |

`IsChild` is no longer serialized. Nothing needs to be: child identity is re-established on the client by the paused add path when a list deserializes its items, exactly as it is when a list `[Fetch]` loads them.

### Behavior change to know about

A modified, valid child **concrete** now reports `IsSavable == true`, where it previously reported `false`. This makes keeping `IsSavable`/`Save()` off child interfaces *more* important, not less — it is the only thing standing between a consumer and an unsupported call.

## Migration guide

**If you read `IsChild`** — there is no replacement property. Pick the mechanism that matches what you were actually asking:

| You were asking | Use instead |
|---|---|
| "Is this a child in an aggregate?" | The interface: child interfaces extend `IEntityBase`, roots extend `IEntityRoot` |
| "What aggregate does this belong to?" | `Root` (`null` on an aggregate root) or `Parent` |
| "Can this be saved?" | `IsSavable` — but only aggregate roots expose it |

**If you caught `SaveFailureReason.IsChildObject`** — remove the case. A child interface has no `Save()`, so the call no longer compiles.

**If you have a child interface extending `IEntityRoot`** — change it to `IEntityBase`. Previously this was merely confusing (`IsSavable` was always `false`). Now it is dangerous: `IsSavable` will report `true` for a modified child, inviting a `Save()` the framework does not support.

**If your save cascade skipped children because `IsSavable` was `false`** — that code was already wrong and this release makes the symptom visible. Children are persisted by their aggregate root's `Save()`; do not gate them on their own savability.
