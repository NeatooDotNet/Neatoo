# Neatoo 0.25.0

**Release Date:** 2026-03-29
**Type:** Feature (Breaking)
**Breaking Changes:** Yes

---

## Summary

`LazyLoad<T>` renamed to `EntityLazyLoad<T>` and now inherits from `Neatoo.RemoteFactory.LazyLoad<T>`. Eliminates duplicated core loading logic. Requires RemoteFactory 0.26.0.

---

## What's New

### EntityLazyLoad inherits from RemoteFactory.LazyLoad

`EntityLazyLoad<T>` extends `Neatoo.RemoteFactory.LazyLoad<T>`, keeping only the Neatoo-specific meta-property interfaces (`IValidateMetaProperties`, `IEntityMetaProperties`). All core loading logic (loader delegate, thread-safe LoadAsync, PropertyChanged, SetValue, serialization support) is provided by the RemoteFactory base class.

### Rename: LazyLoad to EntityLazyLoad

All Neatoo lazy loading types have been renamed to avoid namespace collision with `Neatoo.RemoteFactory.LazyLoad<T>`:

| Before | After |
|--------|-------|
| `LazyLoad<T>` | `EntityLazyLoad<T>` |
| `ILazyLoadFactory` | `IEntityLazyLoadFactory` |
| `LazyLoadFactory` | `EntityLazyLoadFactory` |

The source generator detects `EntityLazyLoad<T>` properties and generates `CreateEntityLazyLoad<T>()` calls.

---

## Breaking Changes

### Type Renames (all in `Neatoo` namespace)

- `LazyLoad<T>` -> `EntityLazyLoad<T>`
- `ILazyLoadFactory` -> `IEntityLazyLoadFactory`
- `LazyLoadFactory` -> `EntityLazyLoadFactory`

### Dependency Update

- Requires `Neatoo.RemoteFactory` 0.26.0 (was 0.24.1)

---

## Migration

1. Find and replace in your code:
   - `LazyLoad<` -> `EntityLazyLoad<`
   - `ILazyLoadFactory` -> `IEntityLazyLoadFactory`
2. Update `Neatoo.RemoteFactory` package to 0.26.0
3. Rebuild to let the source generator regenerate backing fields

No behavioral changes. All existing API surface (Value, IsLoaded, LoadAsync, SetValue, meta-properties) works identically.
