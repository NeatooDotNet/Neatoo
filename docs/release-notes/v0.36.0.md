# Neatoo 0.36.0

**Release date:** 2026-11-24
**Breaking changes:** No

## Summary

Domain code awaits its writes, and rules can trigger on meta state. Every settable partial property
gets a generated `Task Set{Name}(T value)`, so a rule or a verb can await a write together with
everything that write causes. A new analyzer, NEATOO011, names each place a rule or verb assigns
instead, and its code fix rewrites it. A rule can now trigger on `IsValid`, `IsBusy`, `IsModified` and
the other meta properties, so an admission fact such as `CanApprove` is an ordinary rule. Every
MudNeatoo input takes an optional `Setter`, so a control can read a property and write through a verb.

## What's new

### Generated `Set{Name}`: an awaitable write

A property setter cannot be awaited. A rule or verb that assigns a property returns before the rules
that write triggers have finished, async rules included. The generator now emits
`Task Set{Name}(T value)` for every settable partial property:

- On the class, with the setter's semantics. The returned task completes when the write's whole
  cascade has finished.
- On the generated partial `I{ClassName}` interface, for a property with a public setter, when the
  interface is declared `partial` and does not declare the property get-only.

`init`, get-only and lazy-load properties get no `Set{Name}`. A class or base that already declares a
member named `Set{Name}` gets none for that property. The property setter itself is unchanged.

```csharp
RuleManager.AddActionAsync(
    async t => await t.SetTotalAmount(t.Items?.Sum(i => i.LineTotal) ?? 0),
    t => t.Items![0].LineTotal);
```

### NEATOO011: a rule or a verb assigns a partial property

A warning on an assignment to a Neatoo partial property inside:

- a rule body: an `AddAction`, `AddActionAsync` or `AddValidation` lambda, or the `Execute` override
  of a `RuleBase` or `AsyncRuleBase`;
- a verb: a public instance method of the entity that is not a factory operation;
- a non-public helper in the same file that a rule or a verb calls.

Compound assignments and increments are reported too. Factory operations, constructors, object
initializers and generated code are not: inside a factory operation the object is paused, and an
assignment there is the baseline.

The code fix rewrites the assignment to `await t.Set{Name}(v)`. It makes an `AddAction` lambda async
and turns the call into `AddActionAsync`. It is offered where the result compiles: in an async
method or lambda, or an `AddAction` lambda. A synchronous method is left to its author, because
making it `async Task` changes its signature. Fix All is supported, so
`dotnet format analyzers --diagnostics NEATOO011` applies it across a project.

Where no `Set{Name}` exists, the message says why: the interface is not partial, or a member of that
name already exists.

### Rules trigger on meta state

When a meta property changes outside a pause, the rules triggered by that name run:

- on `ValidateBase`: `IsValid`, `IsSelfValid`, `IsBusy`;
- on `EntityBase`, also: `IsModified`, `IsSelfModified`, `IsSavable`, `IsDeleted`.

```csharp
RuleManager.AddActionAsync(
    async t => await t.SetCanApprove(t.Status == "Draft" && t.IsValid),
    t => t.Status,
    t => t.IsValid);
```

A meta-triggered rule runs once per change, is skipped while the object is paused, and is tracked by
`IsBusy` and `WaitForTasks` like any other rule. Whether a set of rules terminates is the author's to
test, as with any two-way rule.

Before this release a trigger expression that named a meta property compiled, and a change to that
meta property did not run the rule. Now it does.

### NEATOO012: an async rule triggered on `IsBusy` or `IsSavable`

An error. An async rule makes the object busy while it runs, so an async rule triggered on `IsBusy`,
or on `IsSavable`, which includes `!IsBusy`, triggers itself without end and `WaitForTasks()` never
returns. A synchronous rule on either is allowed, and NEATOO011 does not ask it to await its writes.

### MudNeatoo: `Setter` on every input

Each of the eleven MudNeatoo inputs takes an optional `Setter` (`Func<T, Task>`). When it is set, a
change calls it, awaited, instead of `EntityProperty.SetValue`. The value, messages, busy and
read-only state still come from `EntityProperty`. A control can therefore read a property and write
through a verb on the entity.

Read-only is unchanged by a `Setter`: the inputs other than the slider still bind `ReadOnly` to
`IsReadOnly`, which is true for a property with a private setter. A verb-bound field over a
private-set property is read-only today
([#130](https://github.com/NeatooDotNet/Neatoo/issues/130)).

### Fixed: work started by a completion callback escaped `IsBusy` and `WaitForTasks`

Work added while `AsyncTasks` ran its sequence-complete callback escaped `IsBusy` and
`WaitForTasks()`. The finishing sequence now stays open for that work. The defect predates this
release; meta-triggered rules made it reachable.

### Fixed: the changed-meta-property list under concurrent writes

`ValidateBase` records which meta properties changed, so that the rules triggered by them can run.
That list was not safe under concurrent property writes from several threads: 1 stress run in 25
failed. It is now locked. The compare and reset of the meta state itself is still not atomic
([#131](https://github.com/NeatooDotNet/Neatoo/issues/131)).

### Skills and documentation

- `skills/neatoo` and `skills/mudneatoo` are at 2.1.0. They teach facts, consequences and intents: a
  fact is a property, a consequence is a rule, an intent is a verb kept for what state cannot hold.
  The mudneatoo skill teaches the component as the unit of refresh: a page subscribes to its root's
  own `PropertyChanged`, and each child row is a component subscribed to its child.
- `docs/VisionAlignment.md` gains statement 8 and rulings D27 to D30.
- New design sample: the TrainingPlan aggregate in
  `src/Design/Design.Domain/Aggregates/TrainingPlanAggregate/`, with its page and components in
  Design.App.
- Design.Domain's verbs that write more than one property are now `async Task`.

## Migration

None required. Existing rules and verbs that assign properties keep working as before.

Two things to expect on upgrade:

- **NEATOO011 is a warning.** A project that builds with warnings as errors fails on each rule or
  verb assignment until it is fixed or the diagnostic is suppressed. Apply the code fix across a
  project with `dotnet format analyzers --diagnostics NEATOO011`, then make the remaining
  synchronous verbs `async Task` by hand.
- **For a generated `Set{Name}` on an interface,** declare the entity's `I{ClassName}` interface
  `partial`.
